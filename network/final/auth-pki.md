# AUTH-PKI.md
## 認証・PKI 直前シート

元のシート: [認証・PKI 暗記シート](../security/auth-pki.md)

### 要点

| 論点 | 覚えること |
| --- | --- |
| 暗号化して送る | **受信者の公開鍵**で暗号化 |
| 署名して送る | **送信者の秘密鍵**で署名 → 公開鍵で検証（**否認防止**） |
| ハイブリッド暗号 | 公開鍵（鍵交換）で**共通鍵を共有**し、データは共通鍵で |
| 鍵の数 | 共通鍵 **n(n−1)/2**、公開鍵 **2n** |
| 証明書の検証 | **CA の署名**、**有効期間**、**失効していないか（CRL・OCSP）**、**ホスト名の一致（SAN）** |
| プライベート CA | **ルート証明書を端末に入れる**（ないと警告） |
| TLS の機能 | **暗号化・サーバの認証・改ざん検知** |
| 前方秘匿性 | **DHE / ECDHE**。秘密鍵が漏れても**過去の通信は復号されない** |
| SNI | Client Hello の**ホスト名**。**暗号化されない** |
| TLS の終端 | LB で終端するなら**サーバ証明書と秘密鍵を LB に** |
| RADIUS | **UDP 1812 / 1813**。AP・スイッチが **RADIUS クライアント** |
| Kerberos | **KDC が TGT・ST** を発行。**時刻同期（NTP）が必要** |
| SAML | **IdP が署名付きアサーション**、SP が**署名を検証**。**ブラウザ経由**でやり取り |
| OAuth / OIDC | **OAuth は認可（アクセストークン）**、**OIDC は認証（ID トークン）** |

### 答えの型

| 問われ方 | 答えの型 |
| --- | --- |
| サーバ証明書で確認すること | 「**接続先のサーバが本物であること**」 |
| クライアント証明書を失効させる理由 | 「**秘密鍵が漏えいした**証明書による**不正な接続を防ぐ**ため」 |
| プライベート CA で警告が出る理由 | 「**ルート証明書が端末に登録されていない**から」 |
| クライアント証明書の利点 | 「**許可した端末だけ**に接続を限定できる」 |
| SAML で署名を検証する目的 | 「**信頼する IdP で作られ、改ざんされていない**ことを確かめる」 |
| Kerberos で時刻同期が必要な理由 | 「チケットの**有効期限の確認に時刻を使う**から」 |
| チャレンジレスポンスの利点 | 「**パスワードが流れず**、盗聴されても**再利用できない**」 |
