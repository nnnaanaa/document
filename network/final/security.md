# SECURITY.md
## セキュリティ 直前シート

元のシート: [セキュリティ 暗記シート](../security/security.md)

### 要点

| 論点 | 覚えること |
| --- | --- |
| FW のルール | **上から順に照合**、最初に一致したものを適用。最後は**暗黙の拒否** |
| ステートフルインスペクション | **行きを許可すれば戻りは自動で許可** |
| DMZ | 公開サーバを置く。外 → 内部 LAN は**すべて拒否**、内部 → 外は**プロキシ経由だけ** |
| FW の冗長化 | **ステートフルフェールオーバ**（セッション情報を同期） |
| IDS / IPS | **IDS は検知だけ**（ミラーポート）、**IPS はインラインで遮断**（誤検知・**バイパス機能**） |
| WAF | Web アプリへの攻撃。**TLS を復号した後**に置く |
| シグネチャ / アノマリ | **シグネチャは未知を検知できない**、**アノマリは誤検知が多い** |
| SYN Flood | **SYN cookie**（確認応答番号が**クッキー ＋ 1**か確かめる） |
| リフレクション | **送信元を偽装**した UDP の要求で、**大きな応答を標的に**。対策は **uRPF** など |
| LAN 内 | **DHCP スヌーピング**、**ダイナミック ARP インスペクション**、**802.1X**、検疫 |
| 標的型攻撃 | **プロキシ必須 ＋ プロキシ認証**、直接通信を FW で拒否、**セグメント分割** |
| インシデント | **LAN から切り離す**（電源は切らない） |

### 答えの型

| 問われ方 | 答えの型 |
| --- | --- |
| DMZ に置く理由 | 「侵害されても**内部 LAN へ直接アクセスされない**ため」 |
| ステートフルの利点 | 「**戻りの通信を自動で許可**でき、ルールを書かなくてよい」 |
| PC の直接通信を拒否する理由 | 「**C&C 通信をプロキシ経由に限定**し、検査・記録するため」 |
| プロキシ認証の効果 | 「**認証情報を持たないマルウェア**の通信を遮断。**誰の通信か**特定できる」 |
| IPS をインラインに置く注意点 | 「**誤検知で正常な通信を遮断**」「**故障時に通信が止まる**」 |
| NAPT 配下の通信元の特定 | 「**変換ログと時刻で突き合わせる**」（だから NTP） |
| リフレクションに UDP の理由 | 「**コネクションレスで送信元を偽装しやすい**」 |
| FW 切替えで切れる理由 | 「**セッション情報を同期していない**」 |
| セグメントを分ける理由 | 「マルウェアの**拡散範囲を限定**するため」 |
