# LB-PROXY.md
## 負荷分散・プロキシ 直前シート

元のシート: [負荷分散・プロキシ 暗記シート](../redundancy/lb-proxy.md)

### 要点

| 論点 | 覚えること |
| --- | --- |
| LB の機能 | **負荷分散**、**ヘルスチェック**、**セッション維持** |
| セッション維持 | 送信元 IP は**プロキシ・NAPT で偏る** → **Cookie** |
| TLS の終端 | Cookie や X-Forwarded-For を使うには **LB で終端** |
| ヘルスチェック | **レイヤ7** でアプリの異常まで見つける |
| X-Forwarded-For | **元の送信元 IP** をサーバに伝える |
| DSR | 戻りが **LB を通らない**。サーバの**ループバックに VIP** |
| GSLB | **DNS** で拠点を振り分け。**TTL を短く** |
| HTTPS の中継 | **CONNECT** → プロキシに中身は見えない |
| HTTPS の検査 | **ルート証明書を PC に入れて**復号 |
| FW | **プロキシ以外の外向き通信を禁止** |

### 答えの型

| 問われ方 | 答えの型 |
| --- | --- |
| セッション維持が必要な理由 | 「セッション情報を**サーバごとに持つ**ので、別サーバでは続けられないから」 |
| 送信元 IP で偏る理由 | 「プロキシ経由だと**送信元 IP が同じ**になるから」 |
| LB で TLS を終端する理由 | 「**暗号化のままでは Cookie を見られない**から」 |
| L7 ヘルスチェックの理由 | 「ポートは開いているが**アプリが応答しない**障害を検知するため」 |
| DSR の利点 | 「**応答が LB を通らず**、LB がボトルネックにならない」 |
| ループバックに VIP の理由 | 「**宛先が VIP のまま**届くパケットを受け取るため」 |
| GSLB で TTL を短くする理由 | 「**キャッシュが早く切れて**別拠点へ切り替わるため」 |
| プロキシ以外を止める理由 | 「マルウェアが**プロキシを通らず外部と通信**するのを防ぐ」 |
