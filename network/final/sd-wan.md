# SD-WAN.md
## SD-WAN 直前シート

元のシート: [SD-WAN 暗記シート](../wan-vpn/sd-wan.md)

### 要点

| 論点 | 覚えること |
| --- | --- |
| コントローラ | **経路情報・IPsec の鍵を配り**、拠点の機器を**一元管理** |
| データの流れ | **エッジ同士が直接**通信し、コントローラは経由しない |
| アンダーレイ / オーバーレイ | **物理回線**と、その上の **IPsec トンネル** |
| トンネル数 | フルメッシュは **n(n−1)/2**（回線が複数なら組合せを掛ける） |
| アプリごとの経路 | **アプリを識別**して**回線を選ぶ** |
| 回線の切替え | **遅延・ジッタ・パケットロス**を監視し、しきい値で自動切替え |
| ローカルブレイクアウト | 本社の負荷を減らす。拠点の**セキュリティ対策（SWG・SASE）**が必要 |
| ゼロタッチプロビジョニング | **現地に技術者が不要** |
| 回線の冗長化 | **別の事業者・別の物理経路** |

### 答えの型

| 問われ方 | 答えの型 |
| --- | --- |
| ローカルブレイクアウトの目的 | 「**本社の回線やプロキシの負荷**を減らし、**SaaS への通信を速く**する」 |
| ローカルブレイクアウトの課題と対策 | 「**本社のセキュリティ対策を通らない**」→「**SWG など（SASE）**を通す」 |
| ゼロタッチの利点 | 「**技術者を派遣せず**に設定を**自動で**行える」 |
| フルメッシュでも設定が増えない理由 | 「**コントローラ**が設定や鍵を**自動で配る**から」 |
| コントローラ停止でも通信が続く理由 | 「通信は**エッジ同士が直接**行うから」 |
| 別事業者・別経路にする理由 | 「同じだと**同時に故障**するおそれがあるから」 |
