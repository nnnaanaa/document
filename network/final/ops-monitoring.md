# OPS-MONITORING.md
## 運用・監視 直前シート

元のシート: [運用・監視 暗記シート](../operation/ops-monitoring.md)

### 要点

| 論点 | 覚えること |
| --- | --- |
| SNMP のポート | **ポーリング UDP 161**（マネージャから）、**トラップ UDP 162**（エージェントから） |
| トラップの弱点 | **届かないことがある** → ポーリングと併用。確認応答付きは **InformRequest** |
| SNMPv3 | **認証と暗号化**あり。v2c のコミュニティ名は平文 |
| 通信量 | **カウンタの差 × 8 ÷ 間隔**。平均なので**バーストは見えない** |
| Syslog | **UDP 514**。**NTP で時刻を合わせる** |
| 誰が帯域を使うか | **フロー情報**で調べる |
| ミラーポート | **取りこぼし**に注意 |
| traceroute | **TTL を増やしながら** Time Exceeded を集める |
| 大きいデータだけ通らない | **MTU**（DF ビット、ICMP の遮断） |

### 答えの型

| 問われ方 | 答えの型 |
| --- | --- |
| トラップだけでは不十分な理由 | 「UDP で**届かなくても再送されない**」「停止すると**通知を送れない**」 |
| ポーリングだけでは不十分な理由 | 「**次の取得までの間**の異常をすぐ検知できない」 |
| 5分平均で分からないこと | 「**短時間の急増**（バースト）」 |
| SNMPv3 にする理由 | 「v2c は**コミュニティ名が平文**で盗聴されるから」 |
| Syslog サーバに送る理由 | 「侵入・故障しても**ログが消えたり改ざんされたりしない**ため」 |
| NTP で合わせる理由 | 「**ログを時刻で突き合わせ**られるようにするため」 |
| フロー情報で分かること | 「**どの端末が、どの宛先と、どのアプリで**使っているか」 |
| 管理用ネットワークを分ける理由 | 「障害時も**機器に接続して調べられる**ため」 |
