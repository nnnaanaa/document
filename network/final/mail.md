# MAIL.md
## メール 直前シート

元のシート: [メール 暗記シート](../protocol/mail.md)

### 要点

| 論点 | 覚えること |
| --- | --- |
| ポート | サーバ間 **SMTP 25**、メールソフトからは **587 ＋ SMTP-AUTH** |
| 受信 | **POP3 110 / IMAP 143**（STARTTLS で途中から暗号化）、**POP3S 995 / IMAPS 993**（最初から TLS） |
| MX | **プリファレンス値が小さいほう**が優先 |
| エンベロープとヘッダ | **別物**。ヘッダ From は簡単に偽れる |
| OP25B | **動的 IP から外部の 25番宛て**を止める |
| SPF | **接続元サーバの IP** を、エンベロープ From のドメインの SPF レコードで確認。**転送に弱い** |
| DKIM | **電子署名**。転送されても検証できる。タグ: **d ＝ ドメイン**、**s ＝ セレクタ**、**p ＝ 公開鍵** |
| DMARC | **ヘッダ From との一致**を確認。扱い **none・quarantine・reject** を宣言、レポート |
| 登録と検査 | DNS に登録するのは**送信側**、検査は**受信側** |
| S/MIME と STARTTLS | **S/MIME は送信者から受信者まで**、STARTTLS は**経路だけ** |

### 答えの型

| 問われ方 | 答えの型 |
| --- | --- |
| 外部の配信サービスで必要な対応 | 「送信サーバの情報を**自社ドメインの SPF レコードに追加**する」 |
| 転送で SPF が失敗する理由 | 「**転送したサーバの IP** が元のドメインの SPF に登録されていないから」 |
| DKIM で分かること | 「**改ざんされていない**ことと、**署名したドメイン**が正しいこと」 |
| DMARC が必要な理由 | 「SPF と DKIM だけでは**ヘッダ From の偽装**を検知できないから」 |
| p=none から始める理由 | 「**レポートで影響を確認してから**厳しくするため」 |
| STARTTLS の弱点 | 「相手が非対応だと**平文**」「**サーバ上では平文**」 |
| OP25B の目的 | 「感染 PC が ISP のサーバを通さず**直接迷惑メールを送る**のを防ぐ」 |
