# OSPF.md
## OSPF 暗記シート

***

エリア・DR/BDR・LSA の基本は [igp.md](igp.md) も参照。

## ひとことで

**OSPF** は、AS の中で使う**リンクステート型**の IGP。各ルータが**同じ地図（LSDB）を持ち**、**ダイクストラ法（SPF）**で**コストの合計が最小**の経路を自分で計算する。

| 項目 | 内容 |
| --- | --- |
| 方式 | **リンクステート型**（リンクの状態 = LSA を交換して LSDB を作る） |
| 経路の計算 | **ダイクストラ法**（SPF アルゴリズム）で最短経路の木を作る |
| メトリック | **コスト**（経路上のコストの**合計が最小**の経路を選ぶ） |
| プロトコル | **IP に直接載る（プロトコル番号 89）**。TCP・UDP は使わない |
| 宛先 | **224.0.0.5**（全 OSPF ルータ）、**224.0.0.6**（DR・BDR） |
| 更新 | 変化があったときだけ LSA を送る（加えて30分ごとに再広告） |
| 特徴 | **収束が速い**、**エリアで大規模に対応**、**VLSM・CIDR に対応**、**ECMP** で負荷分散 |
| 管理距離（Cisco） | **110** |
| IPv6 版 | **OSPFv3** |

## コスト

```text
コスト = 基準帯域 ÷ インタフェースの帯域   （小数は切り捨て、最小は 1）
基準帯域の既定値（Cisco）= 100Mbps
```

| 帯域 | 基準 100Mbps | 基準 10Gbps に変更 |
| --- | --- | --- |
| 10Mbps | 10 | 1000 |
| 100Mbps | **1** | 100 |
| 1Gbps | **1**（100M と区別できない） | 10 |
| 10Gbps | **1** | 1 |

- 既定のままでは **100Mbps 以上がすべてコスト 1** になる → **基準帯域を大きくする**（全ルータで揃える）か、コストを手動で設定する
- 経路のコスト = **宛先までの出力インタフェースのコストの合計**
- 合計が同じ経路が複数あれば **ECMP** で負荷分散する

例）R1 から宛先まで「100M → 1G」と「1G → 1G → 1G」の2経路（基準 10Gbps）→ 100 + 10 = **110** と 10 + 10 + 10 = **30** → 後者が選ばれる

### コストを使った運用

| 目的 | 方法 |
| --- | --- |
| **保守作業の前にルータを迂回させる** | そのルータのインタフェースの**コストを最大（65535）**にする（max-metric）→ 通信が別経路に移ってから作業すれば**通信を止めずに保守**できる |
| 主経路・予備経路 | 予備側のコストを大きくする |
| 負荷分散 | 複数経路のコストの合計を同じにする（ECMP） |

## ネイバーと隣接関係

### Hello パケット

- **Hello** を定期的に送り、ネイバーの発見と生存確認を行う
- 既定値: **Hello 10秒・Dead 40秒**（ブロードキャスト・ポイントツーポイント）。Dead 時間内に Hello が届かないとネイバーダウン
- **パッシブインタフェース**: Hello を送らない（ネイバーを作らない）が、そのネットワークは広告する → **端末だけがつながる LAN 側**に設定する（不要な Hello を流さない・不正なルータとネイバーを作らない）

### ネイバーになるために一致が必要なもの

| 項目 | 補足 |
| --- | --- |
| **エリア ID** | 同じリンクの両端は同じエリア |
| **サブネット（マスク）** | 同じセグメント |
| **Hello / Dead 間隔** | 片方だけ変えるとネイバーにならない |
| **認証**（種類とキー） | ネイバー認証 |
| スタブフラグ | スタブエリアかどうか |
| MTU | 違うと ExStart / Exchange で止まる |

- 逆に**ルータ ID は一致してはいけない**（重複するとネイバーにならない・LSA が正しく扱われない）

### ネイバーの状態

```text
Down
 |
 v
Init
 |
 v
2-Way      <-- DROther どうしはここで止まる（正常）
 |
 v
ExStart
 |
 v
Exchange
 |
 v
Loading
 |
 v
Full       <-- LSDB の同期が完了（隣接関係）
```

| パケット | 役割 |
| --- | --- |
| Hello（Type 1） | ネイバーの発見・維持、DR/BDR の選出 |
| DBD（Type 2） | LSDB の目次を交換 |
| LSR（Type 3） | 足りない LSA を要求 |
| LSU（Type 4） | LSA を送る |
| LSAck（Type 5） | LSU の受信確認 |

## ルータ ID

| 決まり方（優先順） | 内容 |
| --- | --- |
| 1 | **手動で設定**した値 |
| 2 | **ループバックインタフェース**の最大の IP アドレス |
| 3 | 有効な物理インタフェースの最大の IP アドレス |

- **32bit**（IPv4 アドレスの形式）。OSPFv3 でも 32bit
- **ループバックアドレスを使う**のが一般的 → **物理インタフェースの障害で変わらない**

## DR と BDR

| 項目 | 内容 |
| --- | --- |
| 目的 | **ブロードキャストネットワーク（イーサネット）**で、全ルータ同士が隣接関係を作るのを避ける |
| 選出 | **プライオリティ**が最大（既定 **1**） → 同じなら**ルータ ID が最大** |
| **プライオリティ 0** | **DR・BDR に選ばれない** |
| プリエンプト | **しない**（後から優先度の高いルータが来ても DR は交代しない） |
| 通信 | DROther → DR・BDR へ **224.0.0.6**、DR → 全ルータへ **224.0.0.5** |
| ポイントツーポイント | DR・BDR は**選出しない** |

| ルータ n 台のセグメント | 隣接関係（Full）の数 |
| --- | --- |
| DR がない場合 | **n(n − 1) / 2** |
| DR・BDR がある場合 | **2(n − 2) + 1 = 2n − 3**（各 DROther が DR と BDR に、DR と BDR の間に1本） |

例）6台 → DR なしなら 15、DR・BDR ありなら **9**

## エリア

| 用語 | 内容 |
| --- | --- |
| **バックボーンエリア** | **エリア 0（0.0.0.0）**。**ほかのエリアはすべてエリア 0 に接続**する |
| **ABR**（エリア境界ルータ） | **エリア 0 とほかのエリアの両方に属する**ルータ。エリア間の経路を Type 3 LSA で伝える |
| **ASBR**（AS 境界ルータ） | **OSPF 以外の経路（静的経路・BGP など）を再配布**するルータ |
| 内部ルータ | 1つのエリアにだけ属するルータ |
| **仮想リンク** | **エリア 0 に直接つながらないエリア**を、間のエリア（トランジットエリア）を通して**論理的にエリア 0 につなぐ**。スタブエリアは通れない |

**エリアに分けるメリット**: LSA のフラッディングと SPF の計算が**エリア内に限られる** → LSDB が小さくなる、障害の影響が広がらない、ABR で**経路集約**できる

## LSA の種類

| Type | 名前 | 生成するルータ | 伝わる範囲 |
| --- | --- | --- | --- |
| **1** | ルータ LSA | **全ルータ** | **エリア内** |
| **2** | ネットワーク LSA | **DR** | **エリア内** |
| **3** | ネットワークサマリー LSA | **ABR** | ほかのエリアへ（エリア間の経路） |
| 4 | ASBR サマリー LSA | **ABR** | ほかのエリアへ（ASBR の場所） |
| **5** | AS 外部 LSA | **ASBR** | **OSPF ドメイン全体**（スタブエリアを除く） |
| 7 | NSSA 外部 LSA | NSSA 内の ASBR | **NSSA 内**（ABR で Type 5 に変換） |

### 外部経路の種類

| 種類 | コスト | ポイント |
| --- | --- | --- |
| **E2**（既定） | **外部のコストだけ**（OSPF 内のコストを足さない） | どの ASBR に近くてもコストが同じ |
| **E1** | **外部のコスト ＋ ASBR までの OSPF 内のコスト** | 複数の ASBR があるとき、**近い ASBR** を選ばせたいときに使う |

経路の優先順: **エリア内 → エリア間 → E1 → E2** の順に優先（エリア内が最も優先。コストよりも先にこの順で比べる）

## エリアの種類

| エリア | 入ってこない LSA | 外部への経路 | ASBR を置けるか |
| --- | --- | --- | --- |
| 標準エリア | なし | Type 5 で個別に知る | 置ける |
| **スタブエリア** | **Type 4・5** | ABR が配る**デフォルトルート**（Type 3） | 置けない |
| トータリースタブ（Cisco） | **Type 3・4・5**（デフォルトルートだけ） | デフォルトルート | 置けない |
| **NSSA** | **Type 5**（Type 4 も） | デフォルトルートなど | **置ける**（**Type 7** で広告） |

→ 出口が1つしかないエリアは**スタブにして LSDB と経路表を小さくする**

## 経路集約とデフォルトルート

| 項目 | 内容 |
| --- | --- |
| 経路集約ができる場所 | **ABR**（エリア間の経路）と **ASBR**（外部経路）だけ。**エリアの中では集約できない** |
| 効果 | 経路表が小さくなる、**エリア内の経路の変化がほかのエリアに伝わらない**（SPF の再計算が減る） |
| 設計 | 集約しやすいよう、**エリアごとに連続したアドレスを割り当てる** |
| デフォルトルート | ASBR（インターネットへの出口）が OSPF にデフォルトルートを広告 → 各ルータの経路表を小さくできる |

例）192.168.32.0/24 〜 192.168.35.0/24 → **192.168.32.0/22**

## 認証

| 方式 | 内容 |
| --- | --- |
| なし | 既定 |
| 平文 | パスワードがそのまま流れる（盗聴に弱い） |
| **MD5 / HMAC-SHA** | **共通鍵からハッシュ値を作って付ける**。パスワードは流れない |

- 目的: **不正なルータとネイバーになって偽の経路を受け取る**のを防ぐ（エリアやインタフェースごとに設定）
- OSPFv3 は IPsec または認証トレーラで認証する

## ほかの技術との組合せ

| 論点 | ポイント |
| --- | --- |
| **IPsec VPN 上で OSPF** | IPsec（ポリシーベース）は**マルチキャストを運べない** → **GRE で包んでから IPsec**（GRE over IPsec） |
| **BGP との関係** | インターネットの経路（フルルート）を OSPF に**再配布しない**。社内にはデフォルトルートを流す |
| 静的経路との優先 | 管理距離は静的経路 1、OSPF 110 → 静的経路が優先 |
| **障害検知の高速化** | Dead 40秒は遅い → Hello/Dead を短くするか **BFD** を使う（[reliability.md](reliability.md)） |
| **ECMP** | コストの合計が同じ複数経路を同時に使う |
| VRRP | LAN 側のデフォルトゲートウェイの冗長化（[../redundancy/vrrp.md](../redundancy/vrrp.md)） |

## OSPFv3（IPv6）

| 項目 | OSPFv2 | OSPFv3 |
| --- | --- | --- |
| 対象 | IPv4 | **IPv6**（IPv4 も扱える拡張あり） |
| ネイバーとの通信 | インタフェースの IPv4 アドレス | **リンクローカルアドレス** |
| 宛先 | 224.0.0.5 / 6 | **FF02::5 / FF02::6** |
| ルータ ID | 32bit | **32bit のまま**（IPv6 だけの環境でも手動で設定が必要） |
| 認証 | OSPF ヘッダの認証フィールド | **IPsec**（または認証トレーラ） |
| 単位 | サブネットごと | **リンクごと** |

## 試験でよく問われるポイント

- **リンクステート型、ダイクストラ法、LSDB**、**コストの合計が最小**の経路
- **コスト = 基準帯域 ÷ 帯域**。既定（100Mbps）だと 100M 以上が全部 1 → **基準帯域を変更**
- **保守の前にコストを最大にして迂回させる**（通信を止めずに作業）
- **ルータ ID はループバック**、重複禁止
- **DR/BDR の選出**: プライオリティ（既定 1、**0 は選ばれない**）→ ルータ ID。**プリエンプトしない**
- **全エリアはエリア 0 につなぐ**。つながらないときは**仮想リンク**
- **LSA Type 1・2 はエリア内、Type 3 は ABR、Type 5 は ASBR**
- **スタブエリア**は Type 5 が入らずデフォルトルートで外へ。**NSSA** は ASBR を置ける（Type 7）
- **経路集約は ABR と ASBR だけ**
- **パッシブインタフェース**で端末側に Hello を出さない、**ネイバー認証**で不正なルータを防ぐ
- **Hello / Dead 間隔やエリア ID が違うとネイバーにならない**
- **IPsec 上では GRE で包む**、**OSPFv3 はリンクローカルで隣接**
