## ひとことで

**BGP-4** は、**AS（自律システム）同士**で経路を交換する **パスベクタ型**のルーティングプロトコル（EGP）。

| 項目 | 内容 |
| --- | --- |
| 方式 | **パスベクタ型**: 経路に付いた**パスアトリビュート（AS_PATH など）とポリシー**で最適経路を選ぶ |
| トランスポート | **TCP の 179番ポート**で接続する（信頼性は TCP に任せる） |
| 更新 | 最初に全経路を交換し、以後は**変化した分（差分）だけ** UPDATE で送る |
| ピア（ネイバー） | **手動で相手を指定**して接続する（OSPF のように自動では見つけない） |
| 経路数 | インターネットのフルルートは IPv4 で約100万経路。IGP では扱えない規模 |
| 目的 | 最短経路よりも**ポリシー（どの回線・どの ISP を使うか）**を優先して制御する |

### TCP の 179番ポート

- 接続を受ける側は **TCP の 179番ポートで待ち受け**、接続する側は送信元にランダムな空きポートを使って**宛先 179番**へ接続する
- どちらのルータから接続を始めてもよい → 間にファイアウォールがあれば、**両方向とも宛先 TCP 179番**の通信を許可する
- **OSPF との違い**: OSPF は TCP・UDP を使わず IP に直接載るので、ポート番号ではなく**プロトコル番号 89** で表す

| | BGP | OSPF |
| --- | --- | --- |
| 何の上で動くか | **TCP** | **IP に直接** |
| 番号 | **ポート番号 179** | **プロトコル番号 89** |

## iBGP と eBGP

| 項目 | **eBGP**（異なる AS 間） | **iBGP**（同じ AS 内） |
| --- | --- | --- |
| ピアのアドレス | 直結したインタフェースのアドレスが普通 | **ループバックアドレス**が普通（IGP で到達できるようにしておく） |
| TTL | **1**（直結が前提。ループバック同士なら ebgp-multihop が必要） | 制限なし |
| 広告時の AS_PATH | **自 AS 番号を先頭に追加** | 追加しない |
| 広告時の NEXT_HOP | **自分のアドレスに書き換え** | **書き換えない**（eBGP で受け取ったネクストホップのまま） → **next-hop-self** |
| 受け取った経路の再広告 | iBGP・eBGP ピアに広告する | **iBGP で受け取った経路はほかの iBGP ピアに広告しない** → **フルメッシュ**かルートリフレクタが必要 |
| LOCAL_PREF | 送らない | **送る**（AS 内で共有） |
| 管理距離（Cisco） | **20** | **200** |

### next-hop-self（よく出る）

**NEXT_HOP** は「この宛先へは、このアドレスのルータに向けて送れ」という情報。NEXT_HOP までの行き方は、OSPF などの IGP や直結の経路で調べる。

#### 構成

```text
     ISP (AS 64500)    |          自社 (AS 65000)
                       |
  +-------+    eBGP    |   +----+        iBGP        +----+
  | ISP-R |------------+---| R1 |--------------------| R2 |---- LAN
  +-------+            |   +----+                    +----+
  203.0.113.1          |   203.0.113.2   10.0.0.1    10.0.0.2
                       |
  <--- 203.0.113.0/30 ------->  <----- 10.0.0.0/30 ----->
       (ISP との接続)              (社内。OSPF で経路を共有)
```

- 社内の OSPF には **10.0.0.0/30 だけ**を流していて、ISP との接続セグメント 203.0.113.0/30 は流していない
- R2 は **203.0.113.1（ISP-R）への行き方を知らない**

#### インターネットの経路 198.51.100.0/24 が届くまで

| 手順 | 広告 | NEXT_HOP | ポイント |
| --- | --- | --- | --- |
| 1 | ISP-R → R1（**eBGP**） | **203.0.113.1**（ISP-R） | eBGP は NEXT_HOP を**送信元の自分**に書き換えて送る |
| 2 | R1 → R2（**iBGP**） | **203.0.113.1 のまま** | iBGP は NEXT_HOP を**書き換えない** |
| 3 | R2 が経路表に入れるか判断 | 203.0.113.1 | **R2 は 203.0.113.1 への行き方を知らない → この経路は使えない** |

#### R2 から見た BGP の経路

| | 宛先 | NEXT_HOP | R2 での状態 |
| --- | --- | --- | --- |
| **next-hop-self なし** | 198.51.100.0/24 | 203.0.113.1 | **使えない**（NEXT_HOP に到達できない） |
| **R1 に next-hop-self を設定** | 198.51.100.0/24 | **10.0.0.1**（R1） | **使える**（R1 に送れば、R1 が ISP-R へ転送する） |

next-hop-self を設定した後、LAN から 198.51.100.x へ通信するときの流れ:

```text
  LAN
   |
   v
  R2      BGP : 198.51.100.0/24 の NEXT_HOP は 10.0.0.1 (R1)
   |      OSPF: 10.0.0.1 へは直結
   v
  R1      BGP : 198.51.100.0/24 の NEXT_HOP は 203.0.113.1 (ISP-R)
   |      直結: 203.0.113.1 へは直結
   v
  ISP-R
   |
   v
  インターネット
```

#### 対策は2つ

| 対策 | 内容 |
| --- | --- |
| **next-hop-self**（R1 に設定） | R1 が iBGP で広告するとき、**NEXT_HOP を R1 自身のアドレスに書き換える**。R2 は R1 への行き方を知っているので使える。**一般的な方法** |
| 接続セグメントを IGP で広告 | 203.0.113.0/30 を社内の OSPF に流し、R2 が 203.0.113.1 への行き方を知るようにする |

- iBGP のピアを**ループバックアドレス**で張っている場合、next-hop-self で書き換わる先は **R1 のループバックアドレス**になる
- 出口（ISP との接続ルータ）が複数あるときは、**それぞれの出口ルータ**に next-hop-self を設定する

### LOCAL_PREF を iBGP では送り、eBGP では送らない理由

LOCAL_PREF は「**自 AS から外へ出るとき、どの出口を使うか**」という**自 AS だけの方針**を表す値だから。

```
          ┌──── 自AS ────────────────┐
ISP A ── R1（LOCAL_PREF 200 を付ける）
          │        └─(iBGP)─ R3
ISP B ── R2（LOCAL_PREF 100）─┘
```

| | 理由 |
| --- | --- |
| **iBGP で送る** | **AS 内の全ルータで出口を揃えるため**。R1 が付けた LOCAL_PREF 200 が R2・R3 に伝わると、全員が「出口は R1（ISP A）」と同じ判断をする。伝わらないと R2 は「iBGP より eBGP を優先」のルールで自分の ISP B を選び、ルータごとに出口がばらばらになる（主・予備の制御ができない、ループの原因にもなる） |
| **eBGP で送らない** | **ほかの AS には意味がなく、送ってはいけないため**。どの出口を使うかはそれぞれの AS が自分の方針で決める（AS は「自律」システム）。隣の AS の LOCAL_PREF に従うと、外部に自分の経路を操作されてしまう。BGP の仕様（RFC 4271）で、**eBGP には送らず、eBGP から受け取っても無視する**と決められている |

- LOCAL_PREF は AS の外に出ない → 制御できるのは**出ていく通信（自 AS → 外）だけ**
- **入ってくる通信（外 → 自 AS）**は、相手の AS に届く情報で制御する: **AS_PATH プリペンド**・**MED**（隣の AS まで届く）・**細かいプレフィックスの広告**・**コミュニティ**（ISP 側の LOCAL_PREF を変えてもらう）→ 下の「通信の方向と制御の方法」の表を参照

## セッションの確立と維持

| 状態 | 内容 |
| --- | --- |
| Idle | 初期状態 |
| Connect / Active | **TCP の 179番ポートへ接続**を試みる（Active のまま止まる = TCP がつながらない） |
| OpenSent / OpenConfirm | **OPEN** を交換（AS 番号・BGP ID・ホールドタイム）し、KEEPALIVE を待つ |
| **Established** | **経路交換ができる状態**。UPDATE を送り合う |

| メッセージ | 用途 |
| --- | --- |
| OPEN | セッションの確立（AS 番号・ホールドタイム・BGP ID・機能） |
| **UPDATE** | 経路の**広告と取り消し（withdraw）** |
| NOTIFICATION | エラーを知らせて**セッションを切る** |
| **KEEPALIVE** | 生存確認。**ホールドタイム内に届かないとセッションを切り、その相手から学んだ経路を消す** |
| ROUTE-REFRESH | 経路の再送を要求（ポリシー変更後などにセッションを切らずに再取得） |

- タイマー（Cisco の既定値）: **キープアライブ 60 秒、ホールドタイム 180 秒**（ホールドタイムは双方の**小さい方**が使われる）
- 障害の検知が遅い → **BFD** と組み合わせると1秒未満で切り替えられる（[reliability.md](reliability.md)）

## パスアトリビュートの分類

| 分類 | 意味 | 属性 |
| --- | --- | --- |
| **ウェルノウン必須** | すべての実装が理解し、UPDATE に**必ず含む** | **ORIGIN**、**AS_PATH**、**NEXT_HOP** |
| ウェルノウン任意 | すべての実装が理解するが、含むかは任意 | **LOCAL_PREF**（iBGP では必須）、ATOMIC_AGGREGATE |
| オプション・トランジティブ | 理解できなくても**ほかの AS へ引き継ぐ** | AGGREGATOR、**COMMUNITY** |
| オプション・非トランジティブ | 理解できなければ捨てる。**隣の AS より先へは伝わらない** | **MED**、ORIGINATOR_ID、CLUSTER_LIST |

| 属性 | 値の意味 | 有効な範囲 |
| --- | --- | --- |
| **LOCAL_PREF** | **大きいほど優先**（既定 100） | **自 AS の中だけ**（iBGP で共有） |
| **AS_PATH** | **短いほど優先**。ループ検出にも使う | インターネット全体 |
| ORIGIN | **IGP（i）< EGP（e）< INCOMPLETE（?）** の順に優先 | ― |
| **MED** | **小さいほど優先**。隣の AS に「こちらの入口から入ってほしい」と伝える | **隣の AS まで** |
| NEXT_HOP | 次に転送するルータのアドレス | ― |
| COMMUNITY | 経路に付ける**タグ**（例: 65000:100）。ポリシーの目印にする | 引き継がれる |

## 最適経路の選択順序

上から順に比べ、差がついたところで決まる（Cisco の実装をもとにした一般的な順序）。

| 順 | 比べるもの | 優先されるほう |
| --- | --- | --- |
| 0 | NEXT_HOP に到達できるか | **到達できる経路だけが候補** |
| 1 | Weight（Cisco 独自、そのルータ内だけ） | **大きい** |
| 2 | **LOCAL_PREF** | **大きい** |
| 3 | 自分で生成した経路か | 自分で生成した経路 |
| 4 | **AS_PATH の長さ** | **短い** |
| 5 | ORIGIN | IGP < EGP < INCOMPLETE |
| 6 | **MED** | **小さい**（既定では**同じ隣接 AS から来た経路どうし**だけで比べる） |
| 7 | eBGP か iBGP か | **eBGP** |
| 8 | NEXT_HOP までの IGP メトリック | **小さい** |
| 9 | ルータ ID など | 小さい（古い eBGP 経路を優先する実装もある） |

覚え方: **「重い（Weight）ローカル（LOCAL_PREF）は自前（自生成）で短く（AS_PATH）、起源（ORIGIN）は低い MED、外（eBGP）が近い（IGP）」**

- そもそも経路表に入れる段階では、**管理距離**で比べられる: **静的経路（1）は eBGP（20）より優先** → 同じ宛先に静的経路があると BGP の経路は使われない
- 経路表の検索は**最長一致**なので、**より長いプレフィックス（細かい経路）**があればそちらが使われる

## 通信の方向と制御の方法（よく出る）

| 制御したい方向 | 使う方法 | しくみ |
| --- | --- | --- |
| **自 AS → 外（出ていく通信）** | **LOCAL_PREF**（Weight） | 自 AS のルータに「この出口を使え」と指示する。**大きい方の出口**から出る |
| **外 → 自 AS（入ってくる通信）** | **AS_PATH プリペンド** | 予備回線側で**自 AS 番号を重ねて**広告 → AS_PATH が長くなり**選ばれにくい** |
| | **MED** | 同じ隣接 AS に対し、入ってほしい回線側を**小さい MED** で広告（**隣の AS が同じときだけ**効く） |
| | **細かいプレフィックスの広告** | 入ってほしい回線で**長いプレフィックス**を広告 → **最長一致**で選ばれる |
| | **コミュニティ** | ISP が用意した値を付けて、ISP 側の LOCAL_PREF を変えてもらう |

### マルチホームの典型パターン

| 構成 | 設定 |
| --- | --- |
| **主回線・予備回線**（2回線を同じ or 別の ISP に） | 出ていく通信: 主回線側の **LOCAL_PREF を大きく** / 入ってくる通信: 予備回線側で **AS_PATH プリペンド** |
| **負荷分散** | アドレスを分割し、回線ごとに別のプレフィックスを細かく広告（両方の回線で集約経路も広告して予備にする） |
| 片方の回線の障害 | **KEEPALIVE が途切れる（ホールドタイム超過）**か BFD で検知 → 経路が取り消され、もう一方に切り替わる |

- 複数の ISP とマルチホームするには、通常は**グローバル AS 番号**と**どの ISP にも属さないアドレス（PI アドレス）**が必要

## ループ防止

| 場所 | しくみ |
| --- | --- |
| AS 間（eBGP） | **AS_PATH に自 AS 番号があれば破棄** |
| AS 内（iBGP） | **iBGP で学んだ経路はほかの iBGP ピアに広告しない**（スプリットホライズン） |
| ルートリフレクタ | **ORIGINATOR_ID**（最初に広告したルータ）と **CLUSTER_LIST**（通過したクラスター ID）で検出 |
| 例外の回避 | **as-override**（相手の AS 番号を自 AS 番号に書き換えて広告）・**allowas-in**（自 AS 番号を含む経路も受け入れる）。同じ AS 番号の拠点を IP-VPN でつなぐときに使う |

## iBGP のフルメッシュ対策

iBGP ルータが n 台ならフルメッシュのセッション数は **n(n−1)/2**（10台で45本）。

### ルートリフレクタ（RR）

| 受け取った相手 | 反射して広告する先 |
| --- | --- |
| **クライアント**から | **ほかのクライアント**、**非クライアント**、eBGP ピア |
| **非クライアント**から | **クライアントだけ**（非クライアントへは送らない）、eBGP ピア |
| eBGP ピアから | クライアント、非クライアント |

- クライアントは **RR とだけ**セッションを張ればよい
- RR を**2台にして冗長化**し、同じ**クラスター ID** を設定してループを防ぐ
- RR は**最適経路だけ**を反射するので、経路の選択肢が減ることがある

### コンフェデレーション

- AS の中を**複数のサブ AS** に分け、サブ AS 間は eBGP のように扱う（外からは1つの AS に見える）

## 経路集約

- 複数の細かい経路を**まとめて広告**（例: 192.168.0.0/24〜192.168.3.0/24 → 192.168.0.0/22）し、経路表を小さくする
- **summary-only** にすると細かい経路は広告しない
- 集約で AS_PATH の情報が失われたことを **ATOMIC_AGGREGATE**、集約したルータを **AGGREGATOR** で示す（**AS_SET** で元の AS を残すこともできる）

## コミュニティ

| 値 | 名前 | 意味 |
| --- | --- | --- |
| 65535:65281 | **NO_EXPORT** | **自 AS（コンフェデレーション）の外に広告しない** |
| 65535:65282 | **NO_ADVERTISE** | **どのピアにも広告しない** |
| 65535:666 | BLACKHOLE | この宛先への通信を**捨ててほしい**（RTBH 用） |
| AS番号:値 | 独自の値 | ISP ごとに「LOCAL_PREF を下げる」などの意味を決めて公開している |

## AS 番号

| 種類 | 範囲 |
| --- | --- |
| 2オクテット AS 番号 | 1〜65,535 |
| ├ グローバル | 1〜64,511（ほか一部予約） |
| └ **プライベート** | **64,512〜65,534**（65,535 は予約） |
| 4オクテット AS 番号 | 65,536〜4,294,967,295 |
| └ **プライベート** | **4,200,000,000〜4,294,967,294**（4,294,967,295 は予約） |

- **プライベート AS 番号はインターネットに広告しない**（ISP が外へ出すときに取り除く）。1つの ISP とだけ接続する顧客や、IP-VPN の拠点で使う
- 4オクテット AS 番号の表記: 65,546 = **1.10**（上位16bit.下位16bit、asdot 表記）

## セキュリティ

| 対策 | 内容 |
| --- | --- |
| **MD5 認証**（TCP MD5 署名） | ピア間で**共通のパスワード**を設定し、なりすましや不正な BGP 接続・TCP RST 攻撃を防ぐ（後継は TCP-AO） |
| **GTSM**（TTL セキュリティ） | eBGP の TTL を 255 で送り、**254 未満なら捨てる** → 遠くからの偽パケットを防ぐ |
| **プレフィックスフィルタ** | 受け取る・広告する経路を限定する（自分のもの以外を広告しない = **経路リーク**の防止） |
| **最大プレフィックス数** | 想定より多い経路を受けたらセッションを切る |
| **RPKI / ROV** | **ROA**（どの AS がどのプレフィックスを広告してよいか）で経路の正しさを検証 → **経路ハイジャック**を防ぐ |
| **RTBH** | DDoS の宛先への経路を、宛先を Null（捨てる）にして BGP で配る → **攻撃元に近いところで捨てる**（ただし宛先への正常な通信も止まる） |
| **BGP Flowspec** | 送信元 IP・宛先ポートなどの**条件と動作（破棄・帯域制限）**を BGP で配り、**攻撃の通信だけ**を捨てる |

## ほかの技術との組合せ（午後でよく出る）

| 論点 | ポイント |
| --- | --- |
| **静的経路と BGP** | 管理距離が小さい**静的経路が優先**。静的経路を消し忘れると BGP の経路が使われない |
| **VRRP と BGP** | BGP の経路を受け取る前のルータが VRRP マスターになると転送できない → **BGP が確立してから**マスターになるよう、プリエンプトを遅らせる（VRRP は BGP の後） |
| **BGP と IGP** | フルルートを IGP に再配布しない（IGP がパンクする）。社内にはデフォルトルートだけ流すことが多い |
| **BFD** | BGP の障害検知（ホールドタイム 180 秒）を高速化 |
| **ECMP** | 複数の同等な BGP 経路を同時に使う（maximum-paths などの設定が必要） |
| **MP-BGP** | IPv4 以外（**IPv6**、MPLS L3VPN の **VPNv4**、**EVPN**）の経路も運べる拡張。アドレスファミリ（AFI/SAFI）で区別する（[../lan/vxlan.md](../lan/vxlan.md)） |
| **MPLS L3VPN** | **RD**（同じアドレスでも顧客ごとに区別）と **RT**（どの VRF に取り込むか）を MP-BGP で運ぶ（[../wan-vpn/mpls.md](../wan-vpn/mpls.md)） |

| **トランジット** | 料金を払って、**インターネット全体への通信を中継**してもらう接続 |
| **ピアリング** | 互いの顧客宛ての通信だけを**無償で交換**する接続 |
| **フルルート / デフォルトルート** | インターネットの全経路 / 0.0.0.0/0 だけ。受け取る経路は回線・機器の性能で選ぶ |
| **経路フラップ** | 経路の広告と取り消しが繰り返される状態（ダンプニングで抑える） |

## 試験でよく問われるポイント

- **TCP の 179番ポート**（OSPF はプロトコル番号 89）、**パスベクタ型**、**差分更新**
- **eBGP は NEXT_HOP を書き換えるが iBGP は書き換えない** → **next-hop-self**
- **iBGP で学んだ経路はほかの iBGP ピアに広告しない** → **フルメッシュかルートリフレクタ**（冗長化はクラスター ID）
- **LOCAL_PREF は大きいほど、MED は小さいほど、AS_PATH は短いほど優先**
- **出ていく通信は LOCAL_PREF、入ってくる通信は AS_PATH プリペンド・MED・細かいプレフィックス**
- **KEEPALIVE がホールドタイム内に届かないとセッションを切って経路を消す** → 予備回線に切り替わる
- **静的経路は BGP より優先**、**VRRP は BGP が確立してからマスターに**
- **プライベート AS 番号は 64,512〜65,534**
- **MD5 認証**、**RTBH**（宛先ごと捨てる）と **Flowspec**（条件で捨てる）の違い
- **as-override / allowas-in**（IP-VPN で拠点の AS 番号が同じとき）
