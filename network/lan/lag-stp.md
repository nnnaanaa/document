# LAG-STP.md
## LAG (Link Aggregation) と STP / BPDU

***

## LAG (Link Aggregation)

L2（データリンク層）の技術。**複数のリンクを束ねて1つの論理的なリンクとして利用する**技術。L2/L3ポートの両方で利用可能で、スイッチ間やスイッチとサーバー間でよく使用される。**Static**に設定する場合と、**LACP**（Link Aggregation Control Protocol）を使用する場合がある。

**メリット**: 帯域拡大, 冗長化, STPと違いブロッキングポートが生じず構成が分かりやすい

| 構成 | 内容 |
| --- | --- |
| **LAGによるL2ネットワーク** | 2つのリンクを**論理的に1つのリンク**として扱う（リンクとは通信経路をさす） |
| **STPによるL2ネットワーク** | ループ防止のために**ブロッキングポート**が生じる |

## BPDU (Bridge Protocol Data Unit)

STPネットワークの構築やループの検出を動的に行うための**制御用フレーム**。

**役割**: ルートブリッジの選定、ループの検出と回避、トポロジーの変更検知、スイッチポートのステート管理

BPDUがあるおかげで、リンク障害等により既存の通信経路が利用不可となった場合、**動的に新たな通信経路**を構築する。各スイッチは、自分の情報をBPDUとして定期的に送信する。**マルチキャストMACアドレス (01:80:C2:00:00:00)** で送信される。

**BPDUのフィールド（一部抜粋）:**

| フィールド | 詳細 |
| --- | --- |
| Root ID（ルートID） | ルートブリッジのブリッジID |
| **Path Cost**（パスコスト） | ルートブリッジまでの距離を示し、帯域幅から計算される。**10Gbps=2 \| 1Gbps=4 \| 100Mbps=19 \| 10Mbps=100** |
| **Bridge ID**（ブリッジID） | **プライオリティ＋MACアドレス**で構成されるSTPスイッチの識別子。ルートブリッジの選出する際に利用される |
| Port ID（ポートID） | **プライオリティ＋ポート番号**で構成されるポートの識別子。ポートの役割を選出する際に利用される |

## ルートブリッジ

STPネットワークの中心となるスイッチ。**全スイッチの基準**となるスイッチで、**ネットワーク内の全通信パスのルート**。各スイッチはルートブリッジに至る最短パス（経路）を選択することでループを回避する。

* BPDU内の**ブリッジID**（プライオリティ＋MACアドレス）フィールドが**最も小さい**スイッチが選出される
* プライオリティを設定した場合: 意図的に特定のスイッチをルートブリッジとして選出できる
* プライオリティを設定しない場合: **MACアドレスの小さいスイッチ**がルートブリッジとして選出される

例）3台のスイッチがそれぞれプライオリティ 20 / 0 / 10 を名乗る場合、**プライオリティが最小（0）のスイッチ**がルートブリッジとして選出される。

## ポートの役割

ルートブリッジが決まった後、**PathCost を比較し、次に Bridge ID（プライオリティ）を比較**して各ポートの役割（DP/NDP）が決まる。

| ポートの役割 | 詳細 | ステータス |
| --- | --- | --- |
| **Root Port (RP)** / ルートポート | 非ルートブリッジにおいて、**ルートブリッジに最も近いポート**。BPDUの受信を担う | Forwarding |
| **Designated Port (DP)** / 指定ポート | **各リンク毎に1つ選出される**ポート。BPDUの送信を担う | Forwarding |
| **Non Designated Port (NDP)** / 非指定ポート（Blocking Portとも） | RPまたはDPのどちらにも選出されなかったポート。BPDUの受信を担う。RPまたはDPとして選ばれたポートと同じリンクに接続されている他のポート | **Blocking** |

## ポートのステータス

* STPネットワークは最終的に **Blocking** 又は **Forwarding** ステータスのポートで構成される
* Blocking から Forwarding の間に、STPネットワークを構築中であることを示す **Listening** や **Learning** ステータスを経由する

各ステータスは、ポートがデータフレームを送受信できるか、またMACアドレス学習を行えるかを定義している。

| ポートのステータス | 詳細 | データ転送 | MACアドレス学習 |
| --- | --- | --- | --- |
| Disabled | 管理者によりポートがシャットダウンされた状態 | × | × |
| **Blocking** | BPDUの受信のみ行う状態 | **×** | × |
| Listening | ポート選出のためにBPDUを送受信する状態 | × | × |
| Learning | ポート選出のためにBPDUを送受信する状態（Listening → Learning） | × | ○ |
| **Forwarding** | ポートがアクティブになり、実通信の送受信が可能な状態（Listening → Learning → Forwarding） | **○** | ○ |

## RSTP と MSTP

| プロトコル | 標準 | 内容 |
| --- | --- | --- |
| **RSTP** (Rapid STP) | **IEEE 802.1w** | STPを改良して**高速なコンバージェンス（収束）**を実現。**NDPの代わりに AP (Alternate Port) と BP (Backup Port) を設けて高速化** |
| **MSTP** (Multiple STP) | **IEEE 802.1s** | RSTPを改良し、**複数のVLAN（インスタンス）毎にSTPネットワークを構築可能**。大規模なネットワークで高速なコンバージェンスや負荷分散を実現可能 |

* **AP**: RP (Root Port) のバックアップとして動作し、RPダウン時にその役割を即座に引き継ぐ
* **BP**: DP (Designated Port) のバックアップとして動作し、DPダウン時に即座にその役割を引き継ぐ

STPやRSTPは基本的に1つのSTPネットワーク（ツリー）を構築するが、MSTPでは複数のVLANをまとめた**インスタンス**という単位ごとにツリーを構築可能。インスタンス毎にブロッキングポートを調整することで負荷分散も可能。
